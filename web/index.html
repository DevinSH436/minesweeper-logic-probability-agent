⚑ Logic and Probability for Safe Moves · a Minesweeper-playing agent · COMP 8700
COMP 8700 · Introduction to AI · Course project

An agent that proves which squares are safe, and when it can't, takes the smallest risk.

Minesweeper is a partially observable world: the agent sees only the numbers it has uncovered. Our agent treats those numbers as a knowledge base and uses logical entailment (AIMA Ch. 7) to find squares that are certainly safe or certainly mines, just as the textbook's Wumpus World agent reasons about pits. When logic cannot decide, it computes the exact probability that each square holds a mine (AIMA Ch. 12) and reveals the safest one.

How the agent thinks, every move

1 · Percept
Read the board
Which squares are open and what numbers they show. Mines are never visible.
2 · Knowledge base
Numbers → sentences
Each number n says "exactly n of my hidden neighbours are mines".
3 · Logic (Ch 7)
Prove safe / mine
A square is safe iff no model of the KB puts a mine on it (entailment by model checking).
4 · Probability (Ch 12)
If nothing is proven
Count the consistent mine layouts → exact P(mine) for every square.
5 · Action
Reveal one square
A proven-safe square, or else the one with the lowest P(mine).

Four players, compared on the same boards

Random

Clicks any hidden square. A simple reflex agent that ignores its percepts: the floor every method must beat.

Local rules

Uses only the two single-number rules ("all mines found → rest safe", "hidden = missing → all mines"). Sound but incomplete inference; guesses at random when stuck.

Logic only

Full logical inference over the whole knowledge base, including the total mine count. A goal-based knowledge-based agent. When nothing is entailed it must make a random forced guess.

Logic + probability

The same logic first; when stuck, reveals the square with the lowest probability of a mine. A utility-based agent (maximum expected utility, Ch 12.1).

AIMA Ch. 2 (agents) · Ch. 3 (problem formulation) · Ch. 4.4 (belief states)

The problem and the agent

Before any algorithm, AIMA asks us to pin down the task environment and the kind of agent we are building. This tab does that for Minesweeper.

The game

The board is a grid of squares; some hold mines. Revealing a square either ends the game (a mine) or shows a number: how many of its up-to-8 neighbours are mines. A 0 automatically opens its neighbours. The agent wins when every non-mine square is revealed. We use the three standard sizes: beginner 9×9 with 10 mines, intermediate 16×16 with 40, expert 16×30 with 99. As in the classic game, the first click is always safe (mines are placed after it). Our reasoning players open the centre square.

PEAS description (AIMA 2.3.1)

Performance measureWin the game (reveal every safe square without hitting a mine). Secondary: fewer guesses, less time per move.
EnvironmentA rows×cols grid with a fixed number of mines placed uniformly at random after the first click.
ActuatorsReveal(square). (Flagging is bookkeeping only; it never changes the outcome, so our agent records proven mines internally instead.)
SensorsThe number on every revealed square, which squares are still hidden, and the total mine count.

Problem formulation (AIMA 3.1.1)

StatesThe true world state is (mine layout, set of revealed squares). The agent cannot see it, so it reasons over belief states instead (below).
Initial stateAll squares hidden; the mine total M is known.
ActionsReveal(x) for any hidden square x.

PerceptThe newly shown numbers.
Goal testEvery non-mine square is revealed.
CostNot a path cost: the measure is whether the agent survives, so the objective is the probability of winning.

Classical search (Ch 3) cannot solve this directly: there is no known path to a goal, because the result of each action depends on hidden information. That is why the agent needs the tools of Chapters 4, 7 and 12.

The belief state (AIMA 4.4)

In a partially observable environment the agent keeps a belief state: the set of world states it might be in. For Minesweeper the belief state is the set of all mine layouts that agree with every number seen so far. Revealing a square does not move any mine, so the "predict" step is trivial; the "update" step filters the set by the new number. Each reveal can only shrink the belief state: the agent becomes less confused.

The key link between chapters A square is certainly safe exactly when it is safe in every layout of the belief state. That is the definition of logical entailment in Chapter 7 (KB ⊨ ¬Mx). And if every layout in the belief state is equally likely, the fraction of layouts with a mine on x is the probability of Chapter 12. The belief state is too large to list explicitly, so the agent represents it compactly with logic, as AIMA 4.4 suggests.

Which kind of agent is each player? (AIMA 2.4)

PlayerAIMA agent typeExplanation
RandomSimple reflex agent (randomised)Its action does not depend on the percept at all, only on which squares are still hidden.

State representation: factored (AIMA 2.4.7): one Boolean variable per square, "mine or not". This is exactly the representation that propositional logic (Ch 7) and Bayesian networks (Ch 13) work with.

AIMA Ch. 7 · Logical agents · Core technique #1

Proving squares safe with logic

Minesweeper is the Wumpus World with more squares and better sensors. A breeze says "at least one neighbouring pit"; a Minesweeper number says exactly how many neighbouring mines. The agent's job is the same: separate what it has established from what is merely possible.

1 · The knowledge base

One proposition symbol per hidden square, Mx = "x holds a mine". Every revealed number contributes one sentence, and the mine counter contributes one more:

number n at c  ⟹  exactly n of { My : y a hidden neighbour of c } are true plus the global sentence: exactly M of all Mx are true (M = total mines)

"Exactly n of k" is not a single clause. Written in conjunctive normal form (AIMA 7.5.2) it becomes two families of clauses:

  • at most n: for every set of n+1 of the k squares, at least one is not a mine: C(k, n+1) clauses of negative literals;
  • at least n: for every set of k−n+1 of the squares, at least one is a mine: C(k, k−n+1) clauses of positive literals.

This is the same construction AIMA uses for "exactly one wumpus" (7.4.3), generalised from one to n.

Try it: a number in CNF

Squares are named a, b, c…; ¬a means "a is not a mine". The worst case, k = 8 and n = 4, needs 56 + 56 = 112 clauses for a single number.

2 · Entailment: what does the agent know?

A model is an assignment of true/false to every symbol (AIMA 7.3). The KB entails a sentence α, written KB ⊨ α, when α is true in every model in which the KB is true. The agent asks two questions about every hidden square x:

x is safe  ⇔  KB ⊨ ¬Mx  ⇔  KB ∧ Mx is unsatisfiable
x is a mine  ⇔  KB ⊨ Mx  ⇔  KB ∧ ¬Mx is unsatisfiable the second form is proof by refutation (AIMA 7.5.2): add the opposite and derive a contradiction

3 · How the agent decides entailment

Stage A, single-number rules. Two cheap, sound rules handle most moves. If a number already touches as many proven mines as it shows, its other hidden neighbours are safe. If its unknown neighbours are exactly as many as its missing mines, they are all mines. Each rule uses one sentence at a time, so on its own it is incomplete, the same lesson as "Modus Ponens and And-Elimination alone are not complete" (7.5.1). This stage alone is the Local rules player.

Stage B, model checking. For everything else the agent enumerates models, like TT-ENTAILS? (AIMA 7.4.4), with three improvements that keep it fast:

  1. Only the frontier. Hidden squares that touch no number appear in no number-sentence; they only matter through the global count, which is handled by counting (see the Probability tab), not enumeration.
  2. Independent components. The frontier splits into groups of squares that share no number. Each group is checked separately: a 30-square frontier in three groups of 10 costs about 3·210 instead of 230.
  3. Pruning. Squares are assigned in breadth-first order along the numbers, and a branch is abandoned as soon as any number is overfull or can no longer be filled, the same "early termination" idea DPLL uses (7.6.1).

Every surviving complete assignment is a model. A frontier square that is a mine in no model is entailed safe; one that is a mine in every model is entailed to be a mine. The global mine count is included exactly, so the logic is complete for the whole KB: if the agent finds no safe square, then no sound and complete procedure could have found one (the test suite checks this against brute force).

function ASK-SAFE(percept, M):                    ▸ one agent step
    KB ← sentences from every revealed number   ▸ TELL
    apply single-number rules until no change    ▸ Stage A
    split remaining sentences into components
    for each component C:                        ▸ Stage B
        models[C] ← all assignments of C's symbols satisfying C's numbers
                    (backtracking, pruned on violated numbers)
    combine components with the global count M  ▸ exact integer counting
    safe  ← { x : x is a mine in no consistent model }
    mines ← { x : x is a mine in every consistent model }
    return safe, mines

4 · Soundness, completeness and cost

  • Sound: a square is reported safe only if it is safe in every layout consistent with the evidence, so a proven-safe move can never hit a mine. Thousands of test games confirm the agent never died on a proven move.
  • Complete: model checking over all consistent models finds every entailed square. Resolution (7.5.2) would reach the same conclusions, since it is refutation-complete (the ground resolution theorem), but it would first need the exponentially many "exactly n" clauses above. Counting directly over the numbers is far cheaper.
  • Cost: deciding whether a Minesweeper board is consistent is NP-complete (Kaye, 2000), so no method is fast on every board. In practice, components on real boards stay small (we log the largest one seen), and the agent falls back to an approximation if a component ever exceeds a search budget (counted in the experiments).
What logic cannot do Very often no square is entailed safe: a lone "1" touching two hidden squares is a coin-flip that no amount of logic can resolve. AIMA makes the same point for the Wumpus agent: it can say the risky squares are not provably safe, but cannot say which is less risky. That needs probability (Chapter 12).
AIMA Ch. 12 · Quantifying uncertainty · Core technique #2

When logic runs out: the safest guess

AIMA 12.7 revisits the Wumpus World and computes, for each unvisited square, the probability of a pit. The same calculation, with mines for pits, tells our agent which guess is least likely to end the game.

The textbook template (AIMA 12.7)

In the book's example the agent has felt breezes in [1,2] and [2,1]. Pits occur independently with prior 0.2. The squares split into the frontier (unknown squares next to a breeze) and other squares. Summing over the frontier assignments that are consistent with the breezes, and noting that the "other" squares sum out to 1, gives P(pit in [1,3]) ≈ 0.31 and P(pit in [2,2]) ≈ 0.86. The agent should avoid [2,2]. Three ideas carry over: enumerate only the frontier, keep only consistent assignments, and weight each by how likely it is.

The Minesweeper version

Mines are not independent: there are exactly M of them, placed uniformly at random. So every complete layout that agrees with the numbers is equally likely, and

P(Mx | evidence) = (number of consistent layouts with a mine on x) / (number of consistent layouts)

We never list the unconstrained "interior" squares (AIMA's "other" squares) one by one. Let U be the number of interior squares and R the number of mines not yet proven. A frontier assignment that uses k mines can be completed in C(U, R−k) ways, so it stands for that many full layouts:

P(Mx) = Σfrontier models f with x mined C(U, R−kf)  /  Σall frontier models f C(U, R−kf) every interior square shares one probability: the expected number of interior mines divided by U

All counts are exact Python integers (expert boards produce numbers with dozens of digits), so the probabilities are exact, not estimated. With several independent components, their mine-count distributions are combined by polynomial multiplication (convolution) before the binomial weighting. The tests compare every probability against brute-force enumeration of all layouts.

A worked example, and why the weighting matters

Suppose a revealed 1 touches hidden squares A, B, C, and another revealed 1 touches C, D. There are U = 10 interior squares and R = 3 mines left to place.

Counting frontier models alone would call C the safest frontier square; the correct answer is that C is the most dangerous. A one-mine explanation leaves more mines for the interior, and there are many more ways to arrange those. The agent reveals A or B (0.15), which also beats a blind interior guess (0.17).

Choosing the action: maximum expected utility (AIMA 12.1.3)

Give utility 1 to surviving the move and 0 to hitting a mine. Then EU(reveal x) = 1 − P(Mx), and the rational choice is the square with the smallest mine probability. Ties are common (all interior squares share one value), so we break them toward squares with fewer hidden neighbours, such as corners and edges, which are likelier to be a 0 and open more of the board. That tie-break is a heuristic, not from the book.

A limitation we acknowledge This is a one-step greedy policy: it maximises the chance of surviving the next move, not of winning the whole game. A guess that is slightly riskier but reveals more information can sometimes be better later. The fully optimal policy would require solving a POMDP over belief states; AIMA notes such problems are usually wildly intractable, and poses finding even Minesweeper's best first move as an exercise (Ch 23). We do not attempt it.

The same model as a Bayesian network (AIMA Ch. 13)

Equivalently: each Mx is a root node; each revealed number is a child of its neighbours' M nodes with a deterministic CPT ("the count equals n"); one more node constrains the total. Our frontier enumeration is exactly inference by enumeration (13.3.1) on this network, organised component by component the way variable elimination exploits independence. Sampling methods (13.4) behave poorly here: with deterministic evidence, rejection sampling rejects almost every sample and single-square Gibbs sampling gets stuck. That is one reason we compute exactly.

How the evaluation works · and run it yourself

The main experiment

The experiment asks one question: how much does each AI technique help an agent win? Four players play the same set of boards; everything else is held fixed, so any difference in results comes from the reasoning alone.

1 · Design

Independent variable

The player: Random, Local rules, Logic only (Ch 7), Logic + probability (Ch 7 + 12). Each adds one technique to the one before.

Boards

Beginner 9×9 / 10 mines, intermediate 16×16 / 40, expert 16×30 / 99. First click always safe.

Pairing

Game number s uses random seed s for every player, so the reasoning players face exactly the same mine layouts. Each player's own random guesses use a separate random stream.

Measures

Win rate (95% Wilson interval), McNemar's paired test, guesses per game, squares revealed, mean risk of guesses, calibration, time per analysis.

for board in [beginner, intermediate, expert]:
    for player in [random, local rules, logic only, logic + probability]:
        for seed in 0 .. N-1:
            game   = new board(board size, seed)          ▸ same layout for every player
            result = play(game, player)                    ▸ until won or a mine is hit
            record won?, moves, guesses, risk of each guess, time per analysis
        summarise: win rate + 95% CI, averages, calibration bins
compare players on identical boards: McNemar's test

Are the probabilities right? Calibration

For every guess we stored the probability the agent assigned and whether the square really was a mine. If the probabilities are correct, guesses rated 20% should hit a mine about 20% of the time: points should lie on the diagonal.

Paired comparison on identical boards

"Only A won" counts boards that player A won and player B lost, and vice versa. McNemar's χ² (1 degree of freedom) above 3.84 means the difference is significant at the 5% level; above 10.83, at 0.1%.
